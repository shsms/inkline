* Features

** TODO Next: a mode server for sed, awk, jq and grep

The next big feature. One new mode server program (for example
~inkline-tools~, started as ~inkline-tools --mode jq~, with one inkline
mode per command) colours, underlines errors in, indents and offers
completion items for the scripts these commands take, as csvm does for
its own. inkline itself needs no change. Start with a design pass: a
spec, then a plan.

Suggested order, most payoff for the least work first:
1. A small shared crate for the mode protocol. The protocol code now
   lives inside csvm's server (~src/mode_server.rs~ in csvm-rs); both
   servers would use the crate.
2. jq: ~jaq-syn~ (MIT, jaq's own jq parser) or ~tree-sitter-jq~
   (GPL-3.0-or-later). Colours and errors come from the parser;
   completion offers jq's built-in functions.
3. Regex colouring, shared by grep, sed's ~s///~ and awk's ~/…/~:
   ~tree-sitter-regex~ (MIT) or ~regex-syntax~. Both read Rust/ERE
   syntax, so POSIX BRE (~\(~, ~\{~) needs a small tokenizer of our own.
4. sed: addresses, ~s///~, ~y///~, labels and ~{}~ blocks.
   ~tree-sitter-sed~ 0.18 (MIT) is a small one-person project and may not
   build against the tree-sitter 0.27 inkline pins; sed's grammar is
   small enough to parse by hand.
5. awk, the most work: no parser on crates.io is meant to be reused
   (~frawk~, ~awk-rs~ and ~awkrs~ are whole programs). A tree-sitter awk
   grammar exists on GitHub but not on crates.io: build it from its C
   source, or write a parser. A nice extra: with ~-F,~ and a CSV file
   on the line, ~$3~ gets the column's name as a note, and completion
   offers awk's built-in functions and variables (~NR~, ~NF~, …).

Keep it a separate program rather than a built-in tree-sitter mode
inside inkline, which would grow the library every bash process loads.

** DONE A completion menu under the line

As you type, a menu of possible completions shows under the command, and
the grey text after the cursor shows the rest of one of them. One list
holds items from every source, each row marked with a letter for where it
came from. The top row starts highlighted, ~C-n~ / ~C-p~ move the highlight,
Tab takes the highlighted item, and ~C-g~ hides it. Items match by how they
start, or fuzzily by a setting; the menu and the grey text can each be
turned off. Built in three pieces, each adding sources to the same list:

1. Done: the menu, its keys and drawing, with history (~h~) and Lisp
   (~l~, ~inkline-completion-functions~) as sources.
2. Done: bash's own completion (~c~): commands, files, variables and the
   ~complete~ rules other tools install, run in a copy of the shell with a
   time limit, a late answer shown when it comes.
3. Done: mode servers (~m~), a completion request in the inkline mode
   protocol (~docs/mode-protocol.md~), which a server such as csvm can
   answer with commands, flags, functions and column names.

While ~C-r~ (or ~C-s~) searches the history, the line found is drawn
with its colours after readline's search prompt (~(reverse-i-search)`...':~),
which stays as readline draws it, and the matched text (readline's

** TODO Show earlier accept errors when a later accept function refuses the line

When one function in ~inkline-accept-functions~ fails and a later one
refuses the line (~user-error~ or ~quit~), the line stays for editing
and only the refusal shows under it. The earlier function's error is
never shown: it would have been printed above the command's output,
but the command does not run. Show those errors too, after the refusal
text, joined with ~; ~ as the other hook messages are.

** TODO Colour a double-quoted script that holds a =$= expansion

=csvm "select amount > $min" data.csv= sends the script as typed, quote
marks included, because bash will still expand =$min= (a raw argument).
csvm then sees ="select= as its first word and colours nothing. Either
side could fix it: inkline could send the text inside the quotes with a
note of what is still expanded, or csvm could parse inside the quotes and
move each span one byte on (noted in csvm-rs's todo.org too).

** TODO Say when a mode server never answers

A mode server that is running but never replies costs up to 15 ms on every
key and shows no colour, with nothing to say why. Counting unanswered
requests and showing it in =inkline status= (or turning the server off
after a while) would make this visible.

* Bugs

** TODO Keys typed ahead while inkline reload runs are sometimes lost

Keys typed while ~inkline reload~ runs, before the next prompt shows,
sometimes never reach the next line: they are dropped. It happens
without mode servers too. ~reload_stops_mode_servers~ in
~tests/modes.rs~ waits for the next prompt before it types, to stay
clear of it.

Things to check: which step of the reload drops them (reading
~init.el~ again, binding the layout again, or setting readline's
variables), and whether something there sets the terminal up again in
a way that throws away input not yet read.

** TODO A deeply nested line overflows the stack

A line nested about 5,000 to 8,000 levels deep, such as ~"$(~ typed
over and over, overflows an 8 MB stack in ~args::commands~, which walks
the parse tree by calling itself for each level; ~Lexer::spans~ does
the same at about 16,000 levels. The overflow kills bash. Give both
walks a cap on the depth they go to.

** TODO A large request can hold up a redraw for a second

inkline writes a request to a mode server in one go. When the request is
bigger than the socket can hold (about 180 KB for a socket pair on
Linux), such as a long script pasted as one argument, and the server
reads slowly, the redraw waits for the server to take the rest: up to
a second per server (~SEND_WAIT~ in ~src/mode_server/process.rs~), after
which the server is turned off (~request not read~). ~C-c~ ends the
wait within 20 ms, and turns the server off too. Instead, keep the
part not sent yet and send the rest on later redraws, or while inkline
waits for a key, waiting on the socket until it can be written to as
well.

** TODO A mode server's colours cover a =$( … )= inside a raw argument

inkline keeps bash's colour on =$var= inside an argument a mode server
colours, but not on =$( … )= or backquotes: the server's colours go over
them. The design says every bash expansion keeps bash's colour.

** TODO Mode servers that ignore the end of their input are left running

A mode server is only told to stop by the end of its input. One that
ignores it keeps running after =inkline reload=, after its mode is defined
again, and after bash exits, and they add up.

** TODO A mode server script with no =#!= line cannot start

inkline turns it off with "cannot run", where bash would run it with =sh=.

** TODO Known gaps in finding a command's words

These only cost colours: a backquote inside =${x:-…}=, =$`= in an unquoted
here-document body, =#= inside backquotes, a command on the same line as a
here-document start, and empty backquotes.

** TODO A value that holds itself crashes bash when tulisp prints it

tulisp prints a value into the text of some errors: =car= or =cdr= of a
value that is not a list, and a string or a number read from any other
value. Printing a list that holds itself (made with =setcar=) never ends
and overflows the stack. inkline's settings, and the function that
takes a program and its colours, check each value before reading it
(=src/lisp/values.rs=), but other paths still print: an error's text
shows the form it came from, =inkline eval= prints its result, the hook
variables are walked with =base_iter=, and other functions read or print
their arguments unchecked, such as position arguments,
=inkline-unbind-defaults=, =inkline-set-readline-variable=, =upcase=,
=downcase=, =keymap-global-set=, =insert=, and every function with a
string or number argument. A limit on how deep tulisp prints a value
would fix it for every caller.

In =echo "$(csvm "…=, the open quote found first is the outer one, so the

** TODO One blank after a backslash stays inside a script

When C-j adds a line inside a script, a blank right after a backslash is
kept (it may be an escaped space), so it stays at the end of the line
above.

** TODO Esc Esc after Tab no longer lists the choices

In readline's emacs keymap, =M-ESC= (Esc Esc) is also ~complete~: after
a Tab that completed nothing more, it lists the choices, as a second Tab
does. Tab now runs ~menu-take~, so readline records ~menu-take~ as the
last command, and the ~complete~ that Esc Esc runs next does not see a
completion just before it: it does not list. Tab Tab still lists.

** TODO Known limits of a mode server's completion items

- An item is matched against the line's typed text with inkline's own
  quoting, so it can fail to match when the text was escaped some other
  way: =a\b= typed for =ab= does not match an item =ab=.
- With the cursor right after a closing quote, an item that replaces
  typed text inside the quotes is left out; only items for an empty word
  are offered, and they go after the quote, quoted as outside quotes.
- An item that starts with a quote mark also matches against the text
  after that mark only where the mark goes on the line as it is: in a
  =raw= argument, or inside quotes of the other kind. Elsewhere the mark
  is escaped first, so the item starts with a backslash (or, for ='=
  inside single quotes, the item is left out): outside quotes, or inside
  double quotes, =fi= does not find =`first name`=.
- inkline does not skip a backslash-newline when it checks whether a word
  looks like an assignment, as bash does once it joins the lines. So an
  item =a== placed before a typed backslash-newline and =~= is kept, and
  bash expands the =~=.

** TODO The line left on screen after C-o or C-c keeps the region drawn

The line that ~operate-and-get-next~ (=C-o=) runs, or that =C-c= throws

** TODO Write the "single function" check for hooks once

A hook's value is either one function or a list of them. The check for
"one function" is written twice: in Lisp as ~inkline--hook-single-p~
(used by ~add-hook~ and ~remove-hook~) and in Rust as
~is_single_function~ (used by ~functions~ and ~remove~), both in
~src/lisp/hooks.rs~. Register the Rust function as
~inkline--hook-single-p~ and drop the Lisp copy, so the two cannot
drift apart.

** TODO Tidy the mode server code

The line is parsed twice per redraw when a mode is defined (once for
colours, once to find the commands); =src/mode_server.rs= has four separate
paths that read what a server sent (one of them for indentation); the
typing-pause step is written twice, in =show_mode_server_notices= and
=error_to_underline=.

** TODO Keep each mode's colour set with its spans

A mode's colour set is found through range lists that the drawing code
walks side by side with the spans (=span_sets=, =script_sets=). Putting the
set's index in the spans themselves would make "these lists line up" part
of the types.
